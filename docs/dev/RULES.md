# Жёсткие правила Typed

Нарушение любого пункта блокирует релиз.

## Код и поведение

1. Не трогать `controller::tick`, `EXPECT_WINDOW` и `crates/app/src/trial.rs`. Исключение одно: удаление комментариев без изменения токенов (0.3.85).
2. Inno Setup `AppId` всегда `{08E53160-AB9C-43F4-9025-DB168DEDB7D9}`, в `.iss` записан как `{{08E53160-AB9C-43F4-9025-DB168DEDB7D9}`.
3. Идентификатор бандла macOS всегда `app.layoutkeeper`.
4. Теги не переносить, не удалять и не перезаписывать, force-push в теги и в main запрещён.
5. Смену раскладки строчных слов не делать агрессивнее. Короткие строчные 2–3 буквы переключаются только по узкому правилу: редкое слово своей раскладки и одно из самых частых слов другой.
6. Правила исправления опечаток работают только при включённом `fix_typos` и уровне «Обычно» или «Смело». «Осторожно» остаётся на строгих правилах.
7. Только общие правила. Никаких заплаток под одно слово.
8. Рендерер не переводить на wgpu без проверки на Windows. В 0.3.81 wgpu повесил окно настроек.
9. В коде нет комментариев: ни в Rust, включая тесты, примеры и `build.rs`, ни в скриптах, ни в `.iss`, ни в YAML CI. Проверка `scripts/check_no_comments.py` в задаче CI `no-comments`. Это правило распространяется на всё, что публикуется: репозиторий, файлы, посты, документацию.
10. Вендорный код в `third_party/` не правится и проверкой комментариев не охватывается.

## Релизный гейт

1. Ни одна категория проверок не хуже, чем в 0.3.83. Это касается всех метрик `scripts/release_gate.py`: прогона `typist_sweep`, `correction_eval`, `context_eval` и тестеров `typist_eval`.
2. `typist_real_failures` проходит на 100%: все случаи, которые присылал пользователь.
3. `correction_eval`: курируемые ложные срабатывания не больше 7 из 315, частые слова 0 из 1320.
4. `typo_audit`: 0 ложных и 0 пропусков.
5. Если гейт не пройден, релиза нет. Пользователь получает отчёт со списком провалов.
6. Если цикл изменений не даёт улучшения, его останавливают, оставляют то, что работает, и сообщают о результате.
7. Команды проверок перечислены в `METRICS.md`.

## Интерфейс

1. На домашнем экране пять одинаковых квадратов-разделов в один ряд.
2. Минимум текста.
3. Фон из реалистичных морских фотографий: день в светлой теме, сумерки в тёмной. Без клипарта и без полупрозрачной заливки поверх фото.
4. Исключения показываются рядом чипов, длинный путь обрезается, полный виден по наведению.
5. Логотип выбирается в настройках из пяти вариантов. По умолчанию пляж. Без супрематизма и Малевича.
6. Всегда нужные функции всегда включены и не занимают место в настройках.

## Отчётность

1. Служебные отчёты лежат в `docs/dev/`: `DECISIONS.md`, `ROADMAP.md`, `RULES.md`, `METRICS.md`, `KNOWN_ISSUES.md`, `CHANGELOG.md`. Обновлять их после каждого изменения.
2. Отчёт пользователю начинается с провалов. Никаких «успехов» вместо цифр.
